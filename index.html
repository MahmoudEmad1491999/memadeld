PROJECT 01 / TOOLCHAIN & LANGUAGE
ACTIVE · WIP

Arabic RISC-V Toolchain

An Arabic-source toolchain for RISC-V: assembler, linker, and an emerging programming language called غرة (Ghora). The project explores compiler construction, object files, executable layout, and a development workflow designed around Arabic source code.

C11RISC-V RV64IMELF64Compiler designGNU binutilsQEMUDifferential testing
Repository ↗Roadmap ↗Architecture notes ↗
Documented current state
  • Repository README marks the assembler and linker phases as complete for RV64IM.
  • The Arabic assembler emits ELF relocatable objects; its output is compared against GNU as.
  • The linker creates static executables and is checked against GNU ld behavior.
  • Test workflows include QEMU execution, error tests, and differential fuzzing.
  • The Ghora language and its compiler are under active development; the README says the compiler already builds real programs.
Next on the roadmap
  • Project-owned object format and separate compilation.
  • Further compiler and toolchain development, followed by the later roadmap stages.
Scope note: This is an evolving toolchain and language project. The portfolio does not describe it as self-hosting or as a completed compiler ecosystem.
PROJECT 02 / BARE-METAL FIRMWARE
ACTIVE · EARLY STAGE

STM32F401 Black Pill Firmware

A from-scratch bare-metal firmware foundation for the STM32F401CCU6 (Cortex-M4F). The focus is understanding the device from the reset vector upward: startup, memory layout, core control, and peripheral register definitions without relying on CMSIS or a vendor HAL.

C11STM32F401ARM Cortex-M4FARM GNU ToolchainCMakeLinker scriptsInline assembly
Repository ↗Roadmap ↗CI workflow ↗
Implemented foundation
  • Cross-compiled CMake project using the ARM embedded toolchain and a freestanding build configuration.
  • Hand-written linker script for the STM32F401CC memory map.
  • Startup code with a 98-entry vector table, reset handler, .data/.bss initialization and weak default interrupt handlers.
  • Core CPU helpers for interrupt control, barriers, low-power instructions and core-register access.
  • Initial SCB, RCC and GPIO register definitions with compile-time layout checks.
Next on the roadmap
  • Peripheral drivers and host-side tests.
  • Renode boot verification and first GPIO integration test.
  • Serial, DMA, timers, buses and later kernel/bootloader work.
Scope note: The current description is deliberately limited to the bare-metal bring-up foundation. The repository roadmap still lists the first Renode boot test, peripheral drivers, scheduler and bootloader work as pending; those are not presented as completed features here.
PROJECT 03 / C LIBRARY
ACTIVE · INCREMENTAL

libcdsa — C Data Structures & Algorithms

A portable C11 library being built incrementally, with attention to explicit API contracts, allocation behavior, element ownership, error reporting, and verification. The current implementation is a foundation plus an initial dynamic-array module—not yet the full collection described by the long-term roadmap.

Portable C11CMakeAPI designMemory ownershipASan / UBSanValgrindGCC / Clang CI
Repository ↗Roadmap ↗Vector API ↗
Implemented foundation
  • Common status/error codes and allocator hooks, including a failing-allocator test helper.
  • Callback types for comparison, hashing, copying and cleanup, with default helpers.
  • Opaque dynamic-array type with create/destroy, push/pop, get/set, insert/erase, reserve, shrink and clear operations.
  • Documented element ownership and failure behavior in the vector API.
  • CI matrix for GCC and Clang; checks include ASan/UBSan, Valgrind when available, cppcheck and clang-tidy when installed.
Next on the roadmap
  • Complete vector iteration and randomized differential testing.
  • Additional sequences, hashing structures, trees, heaps and algorithms.
Scope note: The current module set is intentionally small. The broader data-structure and algorithm catalogue is a roadmap, not an implemented feature list.
